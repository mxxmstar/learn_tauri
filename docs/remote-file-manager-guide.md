# SSH 远程文件管理工具开发与使用说明（第四版）

## 1. 本次第四版完成了什么

第四版是在前三版基础上的继续增强，目标是把“远程浏览”进一步升级成“远程维护”。

当前已经具备的能力如下：

1. 通过 SSH 用户名 + 密码连接远程虚拟机。
2. 连接前先探测并确认 SSH 主机指纹。
3. 浏览远程目录与文件列表。
4. 查看远程文件 / 目录属性。
5. 右键文件或目录弹出上下文菜单。
6. 下载远程文件到本地。
7. 上传本地文件到远程目录。
8. 打开文本文件进行本地预览。
9. 在文本预览窗口中直接编辑内容。
10. 将编辑后的文本直接保存回远程主机。
11. 新建远程目录。
12. 重命名远程文件或目录。
13. 删除远程文件。
14. 删除空目录。
15. 页面入口独立放在顶部菜单栏 `SSH` 中，并位于 `帮助` 前面。

换句话说，第四版已经把“连接 -> 浏览 -> 下载 / 上传 -> 文本编辑 -> 保存回远程”这一条主流程打通了。

## 3. 用户使用流程

## 3.1 建立 SSH 连接

进入 SSH 页面后，需要填写：

1. 主机地址
2. 端口
3. 用户名
4. 密码
5. 初始目录

连接流程如下：

1. 前端先调用 `ssh_probe_host` 探测主机指纹。
2. 后端只做握手，不进行登录。
3. 后端返回远程主机指纹。
4. 前端弹出确认框，让用户确认是否信任该主机。
5. 用户确认后，前端再调用 `ssh_connect`。
6. 后端按照“严格指纹比对”方式真正建立 SSH 会话。

如果同一主机的指纹发生变化，页面会再次给出警告，避免误连到错误主机。

---

## 3.2 浏览目录

连接成功后，页面会显示：

1. 当前目录路径
2. 面包屑导航
3. 文件列表表格
4. 返回上级按钮
5. 刷新按钮
6. 当前连接信息

交互规则：

1. 双击目录会进入目录。
2. 双击常见文本文件会直接打开文本窗口。
3. 右键文件或目录会弹出操作菜单。

文件表格中的名称列支持右键菜单。

当前右键菜单包含：

1. 进入目录（仅目录）
2. 打开文本（仅文本文件）
3. 下载到本地（仅普通文件）
4. 重命名
5. 删除
6. 显示文件属性

这部分已经满足你最初提出的“右键点击文件弹出菜单”的核心要求。

---

## 3.4 文本文件本地打开与第四版编辑回写

第四版最重要的新增能力，就是把文本预览窗口升级成了“可编辑窗口”。

现在的行为是：

1. 用户打开文本文件时，后端先把远程文件下载到本地缓存目录。
2. 如果文件扩展名属于常见文本类型，后端读取文本内容并返回给前端。
3. 前端在弹窗中用可编辑的文本框展示内容。
4. 用户修改后，可以点击“保存回远程”。
5. 前端调用新的 `sftp_save_text_file` 命令。
6. 后端以覆盖写入的方式把文本内容写回原远程路径。
7. 保存成功后，页面会刷新当前目录，并更新文件大小显示。

弹窗中还额外加入了：

1. “当前内容是否已修改”的状态提示
2. “恢复原内容”按钮
3. “保存回远程”按钮

这样用户在修改文本时不会丢失状态感，也更清楚当前内容是否已经写回远程主机。

## 5.3 第四版新增命令

文件：

- `src-tauri/src/ssh_v3.rs`
- `src-tauri/src/lib.rs`

第四版新增并注册的命令：

- `sftp_save_text_file`

它的实现思路很直接：

1. 校验会话是否存在。
2. 规范化远程路径。
3. 如果目标路径存在且是目录，则拒绝保存。
4. 以 `CREATE | TRUNCATE | WRITE` 方式打开远程文件。
5. 将前端传入的 UTF-8 文本覆盖写入远程文件。
6. 执行 `flush` 与 `shutdown`。
7. 返回远程路径、文件大小和耗时。

这意味着第四版保存行为目前是“整文件覆盖写入”，不做增量 patch。

这样的好处是实现简单、链路稳定，适合当前阶段。

---

## 5.4 本地缓存策略

文本打开时，并不是“直接编辑远程流”，而是采用本地缓存策略：

1. 先把远程文件下载到本地缓存目录。
2. 再读取缓存内容用于前端展示。
3. 用户修改后，通过独立保存命令写回远程。

这样做的好处是：

1. 文本预览与编辑体验更稳定。
2. 前端不需要直接处理远程文件流。
3. 保存失败时，至少前端当前编辑内容不会立刻丢失。

### 12.5 第五版递归下载实现思路

递归下载的实现思路是：

1. 先校验目标远程路径确实是目录
2. 递归扫描远程目录树
3. 生成一个“目录创建计划 + 文件下载计划”
4. 在本地先创建目录结构
5. 再按计划逐个下载文件
6. 最后返回整个目录任务的汇总结果

当前策略下：

1. 单个文件的下载仍然复用现有稳定链路
2. 目录递归任务是在它之上做编排
3. 下载完成后会给前端一个总任务结果

---

### 12.6 第五版递归上传实现思路

递归上传的实现思路是：

1. 先校验本地路径确实是目录
2. 递归扫描本地目录树
3. 生成一个“远程目录创建计划 + 文件上传计划”
4. 先在远程把目录层级建立出来
5. 再按计划逐个上传文件
6. 最后返回整个目录任务的汇总结果

这套实现的好处是：

1. 目录结构和文件传输职责清晰
2. 出现问题时容易定位是“建目录失败”还是“传文件失败”
3. 与原有单文件上传逻辑兼容度高

---

### 12.7 第五版当前边界

第五版虽然已经支持目录递归上传 / 下载，但当前仍然保留这些边界：

2. 暂不支持递归处理符号链接
3. 暂不支持断点续传

1. 右键菜单中的“删除”继续保留
2. 当目标是目录时，确认文案明确提示“会删除目录内全部内容”

3. 功能能力直接升级

---

### 13.4 第六版后端变化

涉及文件：

1. `src-tauri/src/ssh_v3.rs`

这次后端核心变化是把 `sftp_delete_path` 从“只支持空目录”升级成了“支持递归删除非空目录”。

新的删除策略是：

1. 如果目标是普通文件或符号链接，直接删除
2. 如果目标是目录，先遍历目录项
3. 递归删除所有子文件和子目录
4. 最后删除目录自身

这里有一个重要细节：

1. 递归删除目录时，先拿到子路径列表
2. 再逐个递归删除
3. 最后再回头删父目录

这样能避免底层 SFTP 会话在递归过程中出现锁持有顺序问题。

---

### 13.5 第六版当前删除边界

虽然已经支持递归删除非空目录，但这一版仍然保留这些边界：

1. 不允许删除根目录 `/`
2. 符号链接仍按单个文件 / 链接处理，不把它当作目录递归展开
3. 删除仍然是高风险操作，因此前端继续保留强确认提示
